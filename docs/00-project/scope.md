# Personal Terminal Companion — 产品边界

> 2026-09-09 由老李确认。当前正式产品名为 **Personal Terminal Companion**；仓库名暂保留 `terminal-list`，避免在 M0 引入迁移成本。

## Goal

让用户不必记住命令名，只需描述“想做什么”，就能找到一张可信、可复制、带风险提示和平台差异的终端命令卡。

核心闭环：

```text
用户意图 → c / pycheat 查询 → 正确命令卡 → 理解风险与平台差异 → 复制并执行
```

## 产品组成

- **正式产品**：`pycheat`、命令卡真源 `cheatsheet.md`、安装与跨平台入口。
- **Beta 能力**：`tk` 及其七个域；冻结扩张，先验证真实使用价值。
- **解释层**：OS / Shell 课程与相关交互放映，用于解释命令背后的系统原理。
- **内容实验区**：芯片架构课程、微架构材料和非终端主题放映。M0 不扩写、不删除；后续依据生命周期决定是否拆仓。
- **辅助工具**：`hi`、`gup`。保留现状，不把它们视为跨平台核心承诺。

## Non-Goals（当前阶段）

- 不做通用知识库、通用 Todo 或完整个人生产力套件。
- 不因新模型或新 Agent 框架重写本地优先架构。
- 不把课程内容数量当作产品完成度。
- 不在缺少真实使用证据时增加新的 `tk` 域。
- 不在 M0 拆仓、改仓库名或重写 `hi` / `gup`。

## 产品原则

1. 离线匹配永远可用；Ollama 是增强层，不是基本功能的前置条件。
2. `cheatsheet.md` 是命令知识真源，不在代码和说明文档复制第二份卡片数据。
3. 强本地命中优先于语义相似；修改排序前必须用 golden queries 回归。
4. 每项“可用”承诺必须有可重复验证；未在真实设备验证的能力明确标注边界。
5. Think wide, build narrow：一次只推进一个可验证闭环。
