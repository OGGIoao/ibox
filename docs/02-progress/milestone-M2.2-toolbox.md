老李确认采用工具目录首页，并接入查端口、根系探测器和文件精灵。

| 项 | 内容 |
| --- | --- |
| Goal | 第一次打开 iBox 的人在同一首页看懂并打开三件现有工具。 |
| Non-Goal | 第三方插件框架、右键菜单安装、自动清理、公开分发。 |

| Technical Boundary | Windows 本机运行。原工具继续维护自己的采集及渲染逻辑，iBox 调用固定的随包脚本，并把产物存到用户目录。 |
| Exit Criteria | 从独立安装的 iBox 走通三项入口，核对监听信息、软件报告、快照入口和精灵卡片。验证路径包含空格与中文时的传参，运行两仓库现有回归。 |

## 参考及决策

- 2026-11-15 查阅 [Setuptools package data](https://setuptools.pypa.io/en/latest/userguide/datafiles.html#package-data) 和 [PowerShell 参数集合传递](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_splatting?view=powershell-5.1)。用包内数据保留 PowerShell、JS 和 HTML 的相对位置，用户输入作为参数传给固定脚本。
- 工具目录沿用已确认的四层字符地图。每个入口一行名称加结果。输入示例移动到工具内部。

## 验证与 Review

- 25 项 Python 测试、56 张命令卡校验、文件精灵 12 项检查和根系探测器 14 项检查均通过。
- 本地构建 `dist/ibox-0.2.0-py3-none-any.whl`。确认 wheel 内有 9 份运行文件及上游许可证，PowerShell 脚本带 UTF-8 BOM。安装后从仓库外启动 `ibox.exe`，确认首页可选三件工具。
- Windows 伪终端中走通已安装包的三项操作。临时 TCP 监听返回正确 PID；中文及空格路径的文件生成精灵卡片，原内容未变；真实软件勘探生成报告；快照菜单可以返回。报告与卡片生成验证使用 `NoOpen`，默认浏览器自动打开待真人试玩时验证。
- 单独用 Windows PowerShell 运行包内快照入口，采集一份真实快照并与模拟的第二份快照生成对比报告。尚无真实软件安装前后的对照样本。

## 推广前的本机 DIY

老李决定先在自己的电脑上完整体验。把自己查清了什么、还查不清什么作为后续迭代依据，走完这轮再考虑推广。

1. 用文件精灵分别打开一份测试文件修改前后的版本，核对卡片和文件指纹的变化，也确认浏览器能自动打开卡片。
2. 用根系探测器查一个自己常用的软件，挑一条记录回 Windows 核对。遇到本来就计划安装或卸载的软件，可用操作前后的快照对比，并核对报告有没有把事实和推断说清楚。
3. 选一个自己会启动和关闭的本地服务，前后查同一个端口。核对程序名和路径，观察关闭后还能不能查到监听。
4. 把必须离开 iBox 才能弄清楚的实际问题记下来，例如深层的内存观察或核心层的指令实验。下一轮从自己真实卡住的一件事开始。
