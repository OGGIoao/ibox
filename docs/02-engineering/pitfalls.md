## A. 排序与检索

### P1 纯语义替换会把强本地命中挤下去
- **症状**：查「强制结束没响应的程序」，`kill` 被排到 `type` 之后。
- **根因**：`nomic-embed-text` 是英文向模型，短中文查询的余弦相似度全挤在 0.5–0.66（区分度仅 0.15–0.22），语义信号几乎不含信息量。
- **修法**：改融合排序 —— 本地分（30–190）占主导；语义相似度按「相对本次查询最佳值」归一到 [0,1] 后 × `SEMANTIC_W=15` 做温和加成。
- **防回归**：强本地命中永远压住语义，只有零本地分的近义卡才被语义抬出。**不要改回纯语义替换**；改排序前先读 `MEMORY.md §2` 与 `pycheat.fused_rank()`。

### P2 ollama 未运行时语义增强静默降级
- **症状**：近义 / 跨语言查询命中率下降，但**不报任何错**，只有开场屏一行提示。
- **根因**：设计上把「没有语义」当作可接受的降级（离线永远可用），所以刻意不打断用户。
- **修法**：保留降级，但开场屏显式提示；`ibox` 启动期探测 ollama 健康度。
- **防回归**：**排查检索质量问题的第一步，是确认 `:11434` 在跑**（2026-09-19 曾因此误判过一次）。

### P3 字段名带后缀 → 整张卡的该字段被忽略
- **症状**：`ollama embeddings` 卡的示例**一直渲染不出来**，且不报错。
- **根因**：卡里写的是 `- 示例(nomic):`，而 `load_cards()` 只认裸字段名 `- 示例:`，带后缀的字段被当未知行丢弃。
- **修法**：统一回裸字段名。
- **防回归**：字段名要么不加后缀，要么同步改 `load_cards()`；`ibox card check` 已能查出字段缺失。

## B. 数据与同步

### P4 两份数据源靠手工 cp 同步，必然漂移
- **症状**：仓库加了卡（如 `lsof`），用户本机搜不到；改名只进了仓库版。
- **根因**：用户级 `~/.config/cheat/cheatsheet.md`（实际生效）与仓库版 `terminal-toolbox/cheatsheet.md`（出厂副本）是两份文件，靠人记得 `cp`。
- **修法**：`ibox card sync`（比对 + `--force` 对齐）。
- **防回归**：加卡一律走 `ibox card insert`（同时写两份），改完跑 `card check` + `card sync`。

### P5 运行副本与本尊漂移（三次）
- **症状**：`~/terminal-toolbox/` 与仓库代码不一致；实际跑的是旧版 `ibox`（`learn` 一度行为异常即因此）。
- **根因**：多了一层「运行副本」，靠手工 `cp` 与仓库同步。
- **修法**：`~/bin/*` 软链直指仓库；运行副本退役为 `~/terminal-toolbox.retired-20260919`。
- **防回归**：**不要再建第二份代码目录** —— 改仓库即改运行行为。

### P6 向量缓存未记模型名 → 换模型误用旧向量
- **症状**：切到 `bge-m3` 后检索质量没有提升（仍在用 nomic 算出的旧向量）。
- **根因**：缓存 key 只按「内容 hash」，不含模型名。
- **修法**：缓存条目加 `model` 字段，模型不匹配自动失效重建。
- **防回归**：任何「按输入内容做缓存」的设计，都要把**影响结果的配置**纳入 key。

## C. 路径与环境

### P7 软链下 `abspath(__file__)` 定位到错误目录
- **症状**：`~/bin/` 里冒出 `__pycache__`（那里根本没有 `.py` 文件）；**新机器 clone 后首次运行静默失败**。
- **根因**：Python 执行软链脚本时 `__file__` **保持软链路径、不 realpath**（而 `sys.path[0]` 会 realpath）。于是 `os.path.dirname(os.path.abspath(__file__))` 得到 `~/bin` 而非真实目录，同目录的 `tk` / `tkcore.py` / `cheatsheet.md` 全部定位失败。
- **隐蔽性**：「能用」依赖三个巧合同时成立 —— `sys.path[0]` 的 realpath 兜住了 import、用户级数据源兜住了读取、`tk` 恰好也是软链。只有首次初始化这类少走的分支才崩。
- **修法**：`ibox:32` / `pycheat.py:60` / `tk:29` 三处改 `os.path.realpath(__file__)`。
- **防回归**：**定位自身同目录资源一律用 `realpath`**；改完在软链下测一次，并用 `HOME=/tmp/fresh ~/bin/<脚本>` 模拟新机器首次运行。

### P8 Windows 默认代码页 cp1252 中文输出崩溃
- **症状**：Windows CI 的 CLI smoke test 失败；HTML checker 随后暴露同类问题。
- **根因**：Windows 默认编码 cp1252，输出中文直接抛异常。
- **修法**：`pycheat.py` / `tk` 启动期统一 `_ensure_utf8_stdio()`；checker 加同一护栏。
- **防回归**：测试主动设 `PYTHONIOENCODING=cp1252` 模拟非 UTF-8 环境。

### P9 出厂副本缺失 → 首次初始化兜底分支崩
- **症状**：Windows 首次运行崩溃。
- **根因**：兜底逻辑是「从脚本同目录复制 `cheatsheet.md` 到用户级」，但仓库源副本当时并没有这个文件。
- **修法**：补齐出厂副本。
- **防回归**：兜底路径必须有测试覆盖（在 `HOME=/tmp/...` 的空环境跑一次）。

## D. 结构与字段

### P10 一个字段兼两职 → 机器无法解析
- **症状**：加卡只能追加到文件末尾，顺序无意义；想按类筛选做不到。
- **根因**：`来源卷` 同时当「分类」与「注释」用 —— 同一个「第六卷」出现 4 种写法、第二卷 8 种，机器没法解析。
- **修法**：拆成三个字段 —— `分类`（受控词表，机器归位）/ `课卷`（受控，`-`｜`2`｜`2,7`）/ `来源卷`（自由文本，供人追溯）。
- **防回归**：**一个字段只承担一个职责**；机器要用的值必须是受控词表，并由 `card check` 校验。

### P11 卡片字段与别名靠自觉 → 悄悄缺了 18 张
- **症状**：18 张卡缺「别名」（别名正是「说人话能命中」的关键）；另有卡缺「示例」。
- **根因**：字段完整性只靠人自觉，没有任何校验。
- **修法**：补齐；`ibox card check` 增加「分类 / 课卷 / 必需字段 / 卡名唯一」四项体检。
- **防回归**：**能让工具校验的约束，绝不靠约定**。

## E. 交互与并发

### P12 秒级时间戳做 id → 同秒碰撞
- **症状**：同秒内多次 `add` 后，列表显示错乱。
- **根因**：id = 秒级时间戳，同秒重复。
- **修法**：改成「时间戳 + uuid 6 位后缀」。
- **防回归**：任何「人可引用的 id」都要保证唯一，别用低精度时间源。

### P13 交互中重搜，范围悄悄变小
- **症状**：搜到 3 张卡后按 `/` 重搜「磁盘」，只在那 3 张里找。
- **根因**：重搜传的是当前结果集 `order`，而非全量 `cards`。
- **修法**：`browse()` 增加全量 `cards` 参数，重搜走全量。
- **防回归**：交互里的「重新搜索」，语义上应等价于一次新查询。

### P14 只实现 termios → Windows 浏览直接失效
- **症状**：Windows 上搜到卡只显示第一张，翻页 / 复制 / 重搜全部无效。
- **根因**：`read_key()` 只有 `import tty, termios` 分支，Windows 无此模块 → 返回 `None` → 浏览循环直接退出。
- **修法**：加 `msvcrt.getch()` 分支。
- **防回归**：承诺跨平台的功能必须有 Windows 路径；缺失时要**明确降级并提示**，而不是静默退出。

### P15 `score_card` 对高频通用词区分度不足
- **症状**：`怎么把文件传到另一台机器` 首位是 `stat`（`scp` 第 2）；`强制结束没响应的程序` 首位是 `top/htop`（`kill` 第 2）。
- **根因**：`文件`、`进程` 这类通用词命中多张卡的别名与正文，累计分压过了真正相关的卡。
- **现状**：属**精度问题非故障**；经三个历史版本对照确认是既有缺陷，非某次改动引入。
- **若动手**：先读 `MEMORY.md §2` 与 `fused_rank()`；改完必须回跑 8 条 golden queries。

- **现状**：风险已识别，行为未改（怕影响日常同步习惯）。

## G. 文档与同步

### P18 改名收尾只覆盖了部分文档，而结论先于核实写出
- **症状**：入口收敛为 `ibox` 后，`README.md` 顶部的工具清单已更新，但「目录结构」「安装（macOS）」「快速上手」三节**仍是旧入口** —— 软链的还是 `hi.sh` / `gup.sh` / `pycheat.py`，写 `alias c='pycheat'`，示例清一色 `pycheat …`，卡数还停在 49。与此同时 `STATUS.md` 却已经写着「README 已按新入口校正」。
- **根因**：按「文件」逐个改，而不是按「所有提及旧名 / 旧结构的位置」扫描；更关键的是**没回头打开文件核实**，就写下了「已校正」的结论。
- **修法**：重写该三节（目录结构补全、安装改为软链 `ibox`、快速上手改为子命令、加卡方式改为 `card insert`、卡数 49→59）；订正 `STATUS.md` 中不准确的表述。
- **防回归**：改名 / 重构后**用 grep 扫全仓库**（`grep -rn "旧名" --include="*.md" .`），而不是凭印象判断「改完了」；**写「已校正」「已同步」这类结论前，必须实际打开文件确认** —— 结论一旦写进 STATUS，会让接手人跳过核实。
