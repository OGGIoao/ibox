# ADR-002：用户面入口收敛为单一 `ibox`

- 状态：Accepted
- 日期：2026-09-14
- 决策者：老Z
- 关系：**部分取代 ADR-001**（覆盖其两条 Non-Goal：「不重写 `hi` / `gup`」「不新增大型交互功能」）

## Context

ADR-001（2026-09-09）把产品边界收窄到 Personal Terminal Companion，并在 M0 期间冻结入口与交互改动。此后从真实使用中暴露出两个问题：

1. **入口记忆负担与理念矛盾**：用户面有 5 个顶层命令（`c` / `pycheat` / `tk` / `hi` / `gup`），命名风格各异（单字母、`py` 前缀、缩写、口语词），都不传达用途。而本产品的核心主张恰是「**你不必记命令名**」——工具自己的名字却要靠记，是理念与实现的直接矛盾。同时 `tk` 把「数据源」当子命令（note / log / gitx / clip / todo），用户被迫记住有哪些数据源。
2. **交互硬伤**（非审美问题，是「用不对 / 用不了」）：
   - Windows 上浏览完全失效：`read_key()` 只实现 termios 分支，`import tty, termios` 在 Windows 必失败并返回 `None`，`browse()` 随即退出 —— 搜到卡片只能看到第一张。
   - 浏览中按 `/` 重新搜索，范围被悄悄缩小到「当前结果集」。
   - `todo` 列表不打印 id，而标记完成的命令要求传 id。

## Decision

1. 用户面收敛为**唯一入口 `ibox`**，子命令按「你要干什么」组织，而非按数据源：
   `how`（查命令怎么用）/ `find`（在自己的数据里搜）/ `add` + `done`（记一条、标记完成）/ `ask`（问本地模型）/ `hi`（机器信息）/ `sync`（一键 git 同步）。
2. `ibox` 是**薄壳，不新建引擎**：`how` 转调 `pycheat`；`find` / `add` / `done` / `ask` 转调 `tk`（动态加载，不复制代码）；`hi` / `sync` 为 Python 实现（原 `hi.sh` / `gup.sh` 逻辑照搬）。
3. 旧名 `c` / `pycheat` / `tk` / `hi` / `gup` **全部保留**为兼容壳 —— 入口重命名的成本必须为 0，否则改名收益会被「改习惯」的代价吃掉。
4. 无子命令时打印**完整使用指南**（正面回应「子命令一下子记不住」）。
5. 修复上述 3 处交互硬伤。

## Consequences

**正面**

- 用户只需记 1 个名字；`ibox` 新增能力即等于全产品新增能力。
- `hi` / `sync` 变为跨平台（Windows 可用），产品承诺从「macOS 为主」变成两端一致。
- 3 处硬伤修复，其中 Windows 浏览失效属于「承诺了跨平台但实际不可用」的实质缺陷。

**代价**

- ADR-001 的「不重写 `hi` / `gup`」「不新增大型交互功能」两条 Non-Goal 被覆盖。
- `docs/00-project/scope.md` 与 README / STATUS 的产品状态描述需同步更新（本轮已更新，待 M0 Review 确认）。
- 入口名变更会让部分既有文档、截图、肌肉记忆需要迁移；兼容壳缓解但不能完全消除。

**不变**

- `pycheat` + `cheatsheet.md` 仍是**正式产品核心**；`tk` 仍**冻结扩域**；离线优先、「不因新模型 / 新 Agent 框架重写本地优先架构」的原则不变。

## Alternatives

- **B：只加 `ibox` 而当别名，不动 `c` / `pycheat` 主路径**。冲突最小，但没有解决「入口分散」与「记不住」的根因，等于多出一个名字。
- **C：维持 ADR-001 边界，只修 3 处 bug**。最稳，但用户已明确提出统一入口诉求，且入口重命名可用兼容壳把成本压到接近 0，因此不作为首选。
