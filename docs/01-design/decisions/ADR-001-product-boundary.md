# ADR-001：以 Personal Terminal Companion 为产品北极星

- 状态：Accepted
- 日期：2026-09-09
- 决策者：老李

## Context

仓库从终端命令清单逐步长出了 `pycheat`、`tk`、OS 课程、芯片架构材料和交互放映。内容彼此有关，但服务的用户任务、验证方法和生命周期已经不同。继续把所有方向都视为同等主线，会让 README、状态、测试与发布承诺持续漂移。

## Decision

将 **Personal Terminal Companion** 定为正式产品：核心任务是“用人话找到并安全使用终端命令”。

- `pycheat` + `cheatsheet.md` 是核心产品。
- OS / Shell 课程是解释层。
- `tk` 暂列 Beta，不扩域，等待使用证据。
- 芯片架构与非终端放映暂列内容实验区；M0 后另行决定保留、迁移或拆仓。
- M0 先建立可信基线，不进行仓库改名或目录大迁移。

## Alternatives

### B：个人计算机学习系统

把工具、课程、芯片和动画统一设计为学习产品。价值潜力较高，但需要新的信息架构、学习闭环和玩家验证，超出当前复杂度预算。

### C：个人实验总仓库

维持所有内容并列。短期迁移成本最低，但无法形成清晰产品承诺，文档和验收会继续漂移。

## Trade-offs

- 收窄边界会让部分已有内容从“主线”降为实验区，但不会删除已有成果。
- 暂不拆仓避免 M0 被文件迁移打断，但需要在文档中明确各目录身份。
- 冻结 `tk` 扩张会推迟新能力，但能先验证哪些域真正有价值。

## Consequences

- 后续 Milestone 必须围绕终端意图查询核心闭环定义。
- README、STATUS、测试和安装示例必须与该边界一致。
- 内容实验区不能被描述为核心产品已完成能力。
